# 再現手順書：GitHub から Supabase にデータを入れて、アプリを動かす

GitHub の `main` ブランチ（<https://github.com/emon0415/DATA-TRIANGLE_261013>）にあるファイルだけで、同じデータ・同じ画面を作り直す手順です。

- 所要時間：30〜40分（埋め込みの待ち時間を含む）
- 費用：OpenAI の埋め込みで約5円（`text-embedding-3-small`）。Supabase は無料枠で足ります
- 何度実行しても重複しません（番号が同じ行は上書きします）。途中で止まっても、その続きから実行できます

## 全体の流れ

| 手順 | やること | 使うファイル |
|---|---|---|
| 1 | リポジトリを取得して、ライブラリを入れる | `requirements.txt` |
| 2 | Supabase でテーブルと検索関数を作る | `SQL/v5_create.sql`、`SQL/v5_search_fts.sql` |
| 3 | 接続情報を `.env` に書く | `.env`（自分で作る。Git には上げない） |
| 4 | 部署・社員を入れる | `initial_load/load_masters.py` |
| 5 | 文書・章・関係者・キーワードを入れる（8ファイル） | `initial_load/load_documents.py` |
| 6 | 章をベクトルにする（OpenAI） | `initial_load/embed_sections.py` |
| 7 | キャリアシートを入れる | `initial_load/load_career_sheets.py` |
| 8 | 看板を作る | `initial_load/build_profiles.py` |
| 9 | 件数を確認して、アプリを起動する | `app.py` |

順番を変えないでください。後ろの手順は、前の手順で入れたデータを参照します（例：文書は部署と社員がないと入りません）。

## 0. 用意するもの

- Supabase のアカウントと、新しいプロジェクト（空のもの）
- OpenAI の API キー
- Python 3.11 または 3.12、Git
- 実行場所は、**すべてリポジトリの直下**（`DATA-TRIANGLE_261013` フォルダ）です

## 1. リポジトリを取得して、ライブラリを入れる

```
git clone https://github.com/emon0415/DATA-TRIANGLE_261013.git
cd DATA-TRIANGLE_261013
python -m venv .venv
```

仮想環境を有効にします。

- Windows：`.venv\Scripts\activate`
- Mac／Linux：`source .venv/bin/activate`

```
pip install -r requirements.txt
```

## 2. Supabase にテーブルと検索関数を作る

Supabase の画面で、**SQL Editor** を開きます。

1. `SQL/v5_create.sql` の中身を、すべて貼り付けて、実行（Run）します。
   - 拡張機能（`vector`、`pgroonga`）と、全テーブル、索引を作ります。
   - `profile_notes`（看板のノート）も、この中に入っています。
2. 新しいクエリで、`SQL/v5_search_fts.sql` の中身をすべて貼り付けて、実行します。
   - 全文検索の関数 `search_sections_fts` を作ります。

次のファイルは、**新しいDBでは実行しません**。

| ファイル | 実行しない理由 |
|---|---|
| `SQL/v3_create.sql` | 古い版（v5 で作り直し済み） |
| `SQL/v4_migration.sql` | v3 から v4 への変更用（v5 に含まれる） |
| `SQL/v5_profile_notes.sql` | 既存のDBに `profile_notes` を足す用（v5_create.sql に含まれる） |

`pgroonga` の作成でエラーが出たら、Supabase の **Database → Extensions** で `pgroonga` を有効にしてから、もう一度実行します。

## 3. `.env` を作る

リポジトリの直下に、`.env` という名前のファイルを作り、次の3行を書きます。

```
SUPABASE_URL=https://（自分のプロジェクト）.supabase.co
SUPABASE_KEY=（書き込みできるキー）
OPENAI_API_KEY=sk-...
```

- `SUPABASE_URL` と `SUPABASE_KEY`：Supabase の **Project Settings → API** にあります（行単位のアクセス制御は使っていない前提です）
- `.env` は `.gitignore` に入っています。GitHub に上げないでください

## 4. 部署・社員を入れる

```
python initial_load/load_masters.py --dry-run
python initial_load/load_masters.py
```

- `--dry-run` は、読むだけでDBに書きません。最初に必ず実行して、「問題なし」と出ることを確認します
- 読むファイル：`initial_load/data/db_load_673.json`
- 入る件数：`departments` 41件、`employees` 772件

コマンドの例（1つ目と2つ目）：

```
python initial_load/load_documents.py --dry-run
python initial_load/load_documents.py

python initial_load/load_documents.py --dry-run initial_load/data/db_load_add80.json
python initial_load/load_documents.py initial_load/data/db_load_add80.json
```

3つ目以降も、同じ形で、ファイル名だけ変えます。

- このとき、章のベクトル（`embedding`）は、まだ空です。次の手順で入れます
- `body_tokens`（全文検索用の分かち書き）と `document_keywords` は、JSONの値がそのまま入ります

## 6. 章をベクトルにする（OpenAI）

```
python initial_load/embed_sections.py --dry-run
python initial_load/embed_sections.py
```

- `--dry-run` で、対象の章の数（6,335件）と、費用の目安が出ます（OpenAI もDBも使いません）
- 実行すると、`embedding` が空の章だけを、OpenAI でベクトル（1,536次元）にして、DBに書きます。費用は約5円です
- 途中で止まっても、もう一度同じコマンドを実行すれば、続きから進みます
- 「statement timeout」（時間切れ）が出たら、少し待ってから、もう一度実行します。ベクトルの索引の更新に時間がかかるためです

## 7. キャリアシートを入れる

```
python initial_load/load_career_sheets.py --dry-run
python initial_load/load_career_sheets.py
```

- 読むファイル：`initial_load/data/career_sheets_mock.json`（455人分）
- 入る先：`profile_notes`（本人が書いた3項目：現在の職務／将来やりたいこと／そのために取り組んでいること）

## 8. 看板を作る

```
python initial_load/build_profiles.py --dry-run
python initial_load/build_profiles.py
```

- `--dry-run` で、看板を作る人数・文章の長さ・例が出ます（DBは読むだけです）
- 実行すると、文書のノート（`profile_notes`）と、看板の文章・ベクトル（`profiles`）が入ります。費用は1円未満です
- 看板は、非公開のメモです。つながりマップ（人を探す・属人化）の判定には使いません

## 9. 件数を確認して、アプリを起動する

Supabase の SQL Editor で、次を実行します。

```sql
select 'departments' as t, count(*) from departments
union all select 'employees', count(*) from employees
union all select 'documents', count(*) from documents
union all select 'document_sections', count(*) from document_sections
union all select 'document_authors', count(*) from document_authors
union all select 'document_keywords', count(*) from document_keywords
union all select '埋め込み済みの章', count(*) from document_sections where embedding is not null;
```

期待する件数：

| テーブル | 件数 |
|---|---|
| departments | 41 |
| employees | 772 |
| documents | 1,483 |
| document_sections | 6,335 |
| document_authors | 2,022 |
| document_keywords | 11,864 |
| 埋め込み済みの章 | 6,335 |

全文検索の関数も確認します。結果が返れば、成功です。

```sql
select * from search_sections_fts('"昇降機" OR "モータ"', 5);
```

アプリを起動します。

```
streamlit run app.py
```

初回は、検索の準備に時間がかかります。**人を探す**で、「納入から15年以上たったエレベーター…」の相談文を入れて、人が出れば、再現できています。

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| `.env に SUPABASE_URL と SUPABASE_KEY が見つかりません` | `.env` が、リポジトリの直下にない、または名前が違う |
| `部署にない部署番号`、`社員にない社員番号` | 文書のJSONと、DBの部署・社員が合っていない。手順4（マスタ）を先に実行したか確認する |
| `ファイルが見つかりません` | JSONのパスは、リポジトリ直下から書く（例：`initial_load/data/db_load_add80.json`） |
| `statement timeout`（手順6） | 少し待って、同じコマンドをもう一度実行する（続きから進む） |
| `pgroonga` の作成でエラー | Supabase の Database → Extensions で `pgroonga` を有効にして、手順2をやり直す |
| 最初からやり直したい | 新しいSupabaseプロジェクトを作って、手順2からやり直すのが安全です。同じプロジェクトで全部消す場合は、SQL Editor で `drop schema public cascade; create schema public;` を実行してから、`SQL/v5_create.sql` を実行します（**そのプロジェクトのデータがすべて消えます**） |

## ファイルとテーブルの対応

| ファイル | 入るテーブル |
|---|---|
| `db_load_673.json`（部署・社員） | departments、employees |
| `db_load_*.json`（文書） | documents、document_sections（`body`・`body_tokens`）、document_authors、document_keywords |
| `embed_sections.py` | document_sections.embedding |
| `career_sheets_mock.json` | profile_notes（本人入力） |
| `build_profiles.py` | profile_notes（文書由来）、profiles |

アプリのデプロイ（Streamlit Community Cloud）は、別の手順です。Main file path は `app.py`、Python は 3.12、接続情報は `.env` ではなく、アプリの **Settings → Secrets** に、同じ3つのキー名で書きます。
